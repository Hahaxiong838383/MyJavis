## 2026-07-07 · R2 本机隐私 Vault 上线（v0.13.0，App+server 双发）

**背景**：记忆架构两层化第二切片——隐私记忆只存用户本机（多租户视角：每个内测用户的隐私在自己电脑，云端零持久化）。

**关键决策**：
1. **分类器三层锚点**（memory-core/privacy.ts，宁多勿漏）：type 全量（safety/location/relationship）+ key 锚点（profile.address/phone 等，profile.name 刻意不进保称呼体验）+ 内容词表兜底（健康/财务/证件/联系方式）。
2. **hold/拉/焚**：命中→云端不落盘→per-tenant 内存队列（cap 200 淘汰最旧）→App 15s 轮询+privacy 同步域事件拉走→写本机 vault.db（tauri-plugin-sql，同构分层 schema+0600 加固）→ack 即焚。拉取与确认分离（落库成功才 ack）；server 重启丢队列=宁丢勿泄 by design，tray 常驻压窗口。
3. **通话注入 = session-context 上行**：通话必发生在 App 内→connected 时把 vault 记忆推 server 内存（POST /api/privacy/session-context）→recall 与云端候选**同池打分**→挂断 DELETE/2h TTL 即弃。**分人红线**：注入按 ownerId 过滤，声纹 A 的隐私绝不进声纹 B 的对话（单测断言）。
4. **脱敏三道防线**（实施中发现的方案盲区，全部落地）：①event_log 原话行回头脱敏（路由命中时）；②**整轮审计脱敏**——一句话同时抽出隐私+普通候选时普通候选的审计也带全句，故轮级敏感预判统一脱敏；③**assistant 回复脱敏**——生产实测抓到 LLM 复述"你对花粉过敏"进 event_log（本地 E2E 无真 LLM 覆盖不到的路径），hasSensitiveContent 命中即存占位，当场修+清洗已泄露行+生产复测零残留。
5. **R2 砍掉"提炼代理端点"**（原方案含）：写入抽取现为纯规则不出网，提炼需求在 R4 巩固时才出现——届时一并做，YAGNI。
6. tray 常驻（P3 提前捆绑）：菜单栏图标+左键显窗+关窗 hide 不退出+Dock 重开恢复；登录自启做成 Settings 可选开关（默认关，用户主权）。

**验证**：privacy.test（分类器正反例/hold-ack/分人/零落盘/审计零内容）+15 套回归零破坏+privacy E2E 9/9（**云端 DB 全 dump 零隐私内容+server 日志零内容**两条硬断言）+recall E2E 13/13+clippy 零告警+preview 降级态验证+生产 E2E（真 LLM 轮 safety 行数不变+dump 零残留复测）。

**已知限制（明示）**：①隐私记忆单机存储，换电脑不同步（Mini 加密备份后置）；②App 离线期间 server 崩溃丢 hold 队列（宁丢勿泄）；③assistant 脱敏按词表判，正常回复含"医院"等词也会被 event 占位（溯源损失小，可接受）。
