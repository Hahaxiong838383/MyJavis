## 0. 产品概述

### 0.1 它是什么

Javis Memory 是 Javis 语音助手的**持久记忆与持续学习子系统**。它让 Javis 跨会话记住用户、随时间演化对用户的理解、并在不牺牲实时响应的前提下逐步塑形稳定的人格与偏好。

### 0.2 它解决什么问题

无状态的语音助手每次对话都"失忆":重复问同样的问题、记不住纠正、无法积累对用户的理解。给语音助手加记忆的难点不在"能不能存",而在三个约束的交叉:

- **实时性:** 语音对话的记忆读取在关键路径上,慢一点就"顿"。
- **可控性:** 不能让一句随口的话永久重写系统对用户的认知(记忆漂移)。
- **可演化:** 系统要既"当天就响应",又"长期越来越懂",且半年后不必推倒重构。

### 0.3 核心论点(护城河在哪)

向量库、图库、记忆框架都是商品化能力,谁都买得到。Javis 真正可防御的不是某个组件,而是两件事:

1. **延迟优先的三路径架构** —— 把"聪明"从实时读路径上彻底剥离。
2. **离线巩固(Autodreaming)** —— 决定记什么 / 忘什么 / 怎么压缩 / 形成什么人格。这是当前行业普遍裸奔的一环。

## 1. 设计原则(决定一切)

1. **延迟优先(latency-first)。** 这是语音产品。记忆读取在实时关键路径上,有硬性延迟预算。图遍历、同步 LLM 反思永远不上热路径。架构先满足延迟,再谈聪明。
2. **护城河在离线巩固,不在框架。** 真正可防御的是"记什么 / 忘什么 / 怎么压缩 / 形成什么人格"。
3. **先证明价值,再加层。** 每加一层(图、反思内核、分类器)都必须由指标暴露的具体缺口触发,而不是"看起来应该有"。
4. **每一层都必须有界、可回滚、可观测。** 任何"学习 / 自适应"机制,都要有幅度上限、能撤销、能审计。这是抗漂移底线,优先级等同于延迟预算。

## 2. 关键约束:延迟预算(架构宪法)

语音一轮 = ASR → **记忆读取** → LLM 首 token → TTS。记忆读取卡顿,用户立刻感到"迟钝"。

| 路径 | 触发时机 | 延迟预算 | 允许做什么 |
|---|---|---|---|
| **热路径(读)** | 每轮实时 | **p95 ≤ ~150–250ms** | 缓存读取、向量召回、偏好/人格查表 |
| **温路径(写 + 在线适应)** | 每轮答完后异步 | 秒级(用户无感) | 准入打分、冲突仲裁、临时偏好/权重更新 |
| **冷路径(夜间)** | 定时批处理 | 分钟级 | 对账提交、压缩、反思、遗忘、人格更新、重建索引 |

**这张表是整个系统的宪法。** 任何组件选型、任何新功能,先问:落在哪条路径?是否违反该路径预算?

## 3. 记忆模型与数据形态

四层认知模型(对应认知科学,也与主流记忆系统的分层一致),每层显式规定结构化程度与实现形态。

| 层 | 内容 | 结构化程度 | 实现形态 | 主要路径 |
|---|---|---|---|---|
| **L0 Working** | 近 2–5 min 流式上下文 | 否 | 原始 turn 序列 / 环形缓冲 | 热(读) |
| **L1 Episodic** | 事件 + 时间线 + 情绪 | 半结构化 | event tuple | 热读 / 温写 / 冷压缩 |
| **L2 Semantic** | 稳定事实与知识 | 结构化 | fact store(KV + embedding + 外键) | 热读 / 冷巩固 |
| **L3 Preference** | 偏好 + 行为倾向 + 人格 | 强结构化 | schema(条件 + 时间有效区间) | 热读 / 温/冷更新 |

### 3.1 数据 schema(参考形态)

**L1 Episodic — 事件元组**
```text
EpisodicEvent {
  id, session_id, timestamp,
  actor,            # user | agent
  content,          # 压缩后的事件描述
  entities: [entity_id],
  emotion?,         # 可选情绪标记
  embedding,
  source_turn_ref
}
```

**L2 Semantic — 事实库**
```text
Fact {
  id,
  subject: entity_id, predicate, object,
  embedding, confidence,
  t_valid_start, t_valid_end,   # 时间有效区间(支持"曾经为真")
  provenance: [event_id],
  status: committed
}
```

**L3 Preference — 偏好 schema(支持条件化与漂移处理)**
```text
Preference {
  id,
  dimension,        # e.g. "ui.color"
  value,            # e.g. "light"
  condition?,       # e.g. "feels_premium == true"
  strength,         # 0..1 强度/置信
  t_valid_start, t_valid_end,
  status,           # committed | provisional
  ttl?,             # 仅 provisional
  provenance, last_reinforced
}
```

### 3.2 关于关系结构与 graph(重要澄清)

entity resolution、冲突消解是**操作**,不一定要落一张持久化的图——带 `entity_id`/外键的事实库就能做。因此 **v1 不引入图引擎**。graph 仅作为"L2 semantic memory 的一种可选内部实现",**当且仅当指标证明需要多跳时间推理**时才引入,且只在温/冷路径,永不上热路径。

### 3.3 关于偏好的条件化(处理"偏好反转")

偏好必须能表达"条件 + 时间有效性",而非单值覆盖。例:

```text
UI配色: value=亮色  [condition: 默认]
UI配色: value=黑色  [condition: feels_premium==true]   # 两条并存, 非覆盖
```

这是处理"用户三天后改口"的数据基础:不是 overwrite,而是条件化共存 + 时间标注。

## 4. 学习的三个时间尺度

让系统"当天变聪明"很重要,但若一句随口的话就永久重塑偏好,就是漂移。正确做法:**三个尺度,越快的尺度作用越临时、越可回滚。**

| 尺度 | 何时 | 路径 | 作用范围 | 持久性 |
|---|---|---|---|---|
| **T0 即时** | 本轮 / 本 session | 热路径 | session 内覆盖 | 临时,session 结束失效 |
| **T1 当天** | 答后异步 | 温路径(在线适应) | 偏好 delta / 检索权重 | **provisional,立即生效但未提交,带 TTL,可回滚** |
| **T2 夜间** | 定时 | 冷路径(对账 + 巩固) | 长期 committed 状态 | 持久,经对账后提交 |

**事务隐喻:** 温路径的更新 = 未提交事务;冷路径对账 = commit / rollback。
"行为变聪明"(online)与"结构变聪明"(offline)都要,但用**提交边界**隔开。这条边界是整个系统可控性的核心。

## 5. 三路径架构

```
                         Javis Voice Agent
                       ASR / LLM / TTS / UI
                     │                       ▲
             读 query│                       │ user reaction
                     ▼                       │ (显式纠正 / 重复 / 中断)
 ══ 热路径 (读, p95 ≤ ~200ms) ══════════      │
   Working memory 缓存                        │
   + 向量召回 (语义 + BM25 + 实体)            │   ┌── 反馈信号 (v1: 仅显式纠正)
   + 偏好/人格查表 (committed + 当天 provisional) │
 ════════════════════════════════════════     │   │
                     │ 对话流 ────────────────┴───┘
                     ▼
 ── 温路径 (答后异步) ──────────────────────────────
   ① Memory Admission & Scoring (准入控制)
        → ignore / store / merge / update / promote / decay (+confidence)
   ② Online Adaptation (provisional · 有界 · 可回滚)
        → 偏好 delta / 检索权重  [立即生效, uncommitted, 带 TTL]
 ───────────────────────────────────────────────────
                     ▼  落盘 (committed 与 provisional 分区)
   Storage: LanceDB / SQLite (local-first)
                     ▲
                     │ 读写
 ── 冷路径 (夜间 = Autodreaming) ────────────────────
   ★ 对账 (reconciliation): provisional → commit / discard
   压缩 (episodic→semantic) · 反思/洞察 · 遗忘/衰减
   · 人格参数更新 · 重建索引 · 矛盾清扫
 ───────────────────────────────────────────────────
```

**两条铁律:**
- 图遍历、同步 LLM 反思永远不上热路径。
- 温路径只写 provisional;只有夜间对账能把它提交进长期 committed 状态。

## 6. 端到端数据流

### 6.1 读流程(热路径,≤ ~200ms)

1. 取 working memory(近 N turns)。
2. **并行**召回:向量(语义)+ BM25(关键词)+ 实体匹配 → 融合取 top-k 压缩事实。
3. 查偏好/人格(committed + 当天 provisional)。
4. 组装 context string 注入 LLM prompt。
   → 无图遍历,无同步 LLM 反思。

### 6.2 写流程(温路径,答后异步)

1. 对话日志入队(用户无感)。
2. 抽取候选记忆(event / fact / preference 信号)。
3. `admit()` 打分 → 决定 action 与目标层。
4. 冲突处理:条件化 / 时间化,不盲目 overwrite。
5. 写 provisional 更新到"未提交区"(在线适应)。
6. 若本轮有显式纠正信号 → 按风险分级注入(见 §9)。

### 6.3 夜间流程(冷路径)

1. 快照 + 版本化。
2. **对账:** 遍历当天 provisional → 提交 / 丢弃。
3. 召回近期 episodic 簇 → 矛盾检测。
4. 压缩(episodic → semantic)。
5. 反思(信念 / 洞察)。
6. 衰减与遗忘。
7. 人格 / 偏好参数更新(committed)。
8. 重建索引 + 写回 + 版本化。

## 7. Memory Admission & Scoring Layer(准入层)

系统的"写入大脑"。心智模型类比**缓存准入 / 替换策略**:不是 DSL,也不是"永远又薄又笨的函数",而是一个**确定性优先、可解释、可回滚**的准入控制层。

### 7.1 接口

```text
admit(event, context, memory_state) -> Decision

Decision {
  action:       ignore | store | merge | update | promote | decay,
  target_layer: episodic | semantic | preference,
  confidence:   0..1,
  conflicts:    [memory_id],   # 若有
  rationale:    string         # 必记录, 供审计与回放
}
```

### 7.2 打分(v1 确定性)

综合几个信号给出动作:
- **salience(显著性):** 是否值得记(信息量、用户强调、情绪)。
- **novelty(新颖性):** 是否已知 → 已知则 NOOP / 强化而非新增。
- **conflict(冲突):** 与现有记忆是否矛盾 → 触发条件化 / 时间化处理。
- **type routing:** 路由到 episodic / semantic / preference。

### 7.3 实现演进(确定性为主轴)

- **v1:** 规则 + 打分(deterministic),每个决策带 rationale 落日志。
- **升级通道(非默认):** 仅**模糊个案**(confidence 落在中间带、或检测到矛盾)升级给 LLM 判官给"建议";最终动作仍由确定性层 + 日志治理。
- **不做:** 默认用 LLM classifier 做准入。目标是"可控、可解释、不漂移",噪声学出来的分类器最难满足这三点。

## 8. Online Adaptation Layer(在线适应,温路径)

让系统当天就响应用户,而不必等到夜里。**但每次在线更新都必须满足"有界 / 可回滚 / 可观测"。**

更新对象:
- **偏好 delta(provisional):** 写进 L3 "未提交区",不动 committed 区。
- **检索权重 / bias:** 调整热路径召回偏置(风险最低)。
- **短期信念调整:** 当天对某些事实的置信微调。

三条护栏:
- **有界:** 单次更新幅度有上限;不被强化则按 TTL 衰减消失。
- **可回滚:** 以 provisional delta 存储,带来源信号 + confidence;夜间对账可整体撤销。
- **可观测:** 每次更新落日志(改了什么、因何信号、置信多少),可审计、可回放。

夜间对账负责:把被反复强化、与既有记忆不矛盾的 provisional **提交**为 committed;把噪声、一次性、自相矛盾的**丢弃**。

## 9. Memory Feedback Loop(反馈闭环)

让系统持续校准。语音场景拿不到干净的点赞点踩,信号又吵又难抽,所以 **v1 只接最便宜、最无歧义的信号,并按风险分级注入。**

```text
User reaction
   ↓  (v1 只取: 显式纠正, 如 "不是, 我说的是 X")
信号抽取 + 置信
   ↓  分级注入 (风险递增 → 阻尼递增)
 ├─ 检索权重       : 风险低 → 可较快调整 (有界, 可回滚)
 ├─ 偏好模型       : 风险中 → 写 provisional, 夜间对账才提交
 └─ 准入策略       : 风险高 → 不自动改写; 产 "提案" 待人审 / 重度阻尼
```

**铁律:反馈信号绝不自动改写准入策略本身。** 准入策略是人审配置,反馈只能给它提"建议",否则系统会用噪声信号改写自己的准入规则,直接漂走。

**信号路线图:** v1 仅显式纠正 → v2 才考虑隐式信号(重复、中断、不耐烦),且仍只喂低风险通道。不要一上来做"满意度推断"。

## 10. Autodreaming(离线巩固,冷路径)

定位:定时批处理,不在关键路径,这里放最贵的推理。**这是护城河。**

夜间流程:
1. 快照 + 版本化
2. **对账:** 当天 provisional → 提交 / 丢弃
3. 召回近期 episodic 簇
4. 矛盾检测
5. 压缩(episodic → semantic)
6. 反思(信念推理)
7. 衰减与遗忘
8. 人格 / 偏好参数更新(committed)
9. 重建索引 + 写回 + 版本化

三类产物:
- **结构更新(structural):** 记忆 / 事实库的重写、合并。
- **行为更新(behavioral):** 偏好与人格模型的变化(committed)。
- **概念洞察(conceptual):** 反思层产出的行为假设。

> 为什么是护城河:主流记忆系统几乎只测"检索";"该留什么"与"遗忘 / 巩固"这一环行业普遍没做。做扎实它,别人短期抄不走。

## 11. 技术栈

主引擎唯一,不并存能力重叠的图系统。选型只看三条:成熟度、是否满足所在路径延迟预算、是否自带时间/实体/冲突处理。所有选择可换。

| 角色 | 默认 | 路径 | 说明 |
|---|---|---|---|
| Working memory | 内存 / Redis | 热 | 近会话环形缓冲 |
| 快速事实层(读) | Mem0 式压缩记忆 + 向量库 | 热 | p95 ~0.2s,落在语音可用区间 |
| 持久化 | LanceDB / SQLite | — | local-first;committed 与 provisional 分区 |
| 准入与打分 | 自研(确定性) | 温 | LLM 仅作模糊个案升级 |
| 在线适应 | 自研(provisional/有界/可回滚) | 温 | 当天变聪明 |
| 反馈闭环 | 自研(v1 仅显式纠正) | 温 | 分级注入 |
| 离线巩固 | 自研 Autodreaming | 冷 | 对账 + 压缩 + 反思 + 遗忘 + 人格 |
| 反思内核(可选) | Hindsight / CARA 式 | 冷 | 隔离在接口后,不上热路径,当实验件 |
| 时间图(可选,按需) | Graphiti | 温/冷 | 仅当多跳时间查询被指标证明必要时 |

## 12. 评估体系(加层之前必须先有;也是新机制的准入闸门)

没有评估,后面所有分层都是凭感觉。**Phase 0 就要建好回放语料 + 指标。**

**基础指标**
- **延迟:** 热路径读取 p95(硬预算,如 ≤ 200ms)
- **检索质量:** 回放语料命中率 / 召回
- **一致性:** 矛盾率
- **成本:** 每轮 token
- **连续性(主观):** 跨 session "它记得我" 评分

**给在线适应 / 反馈把关的指标**
- **漂移率 / 偏好稳定性:** committed 偏好在无强证据下翻转的频率(越低越好)
- **provisional 健康度:** 在线更新的 commit / rollback 比例(落在合理区间)
- **纠正响应:** 用户显式纠正后,系统当轮 / 当天是否修正(越高越好)

公开 benchmark(LongMemEval / LoCoMo)只当 sanity check,**不当目标**——小 benchmark 可被激进检索或大模型刷上去,不代表系统在你的语音负载上变好。

---

## 13. 路线图

- **Phase 0 — 地基:** 延迟预算 + 评估指标(含漂移率 / 纠正响应)+ 回放语料。**(不做不开工)**
- **Phase 1 — 最薄热路径读闭环:** Working memory + 向量召回 + 偏好查表。证明它让语音对话变好。量化。
- **Phase 2 — 温路径:** 准入打分(确定性)+ 在线适应(provisional / 有界 / 可回滚)+ 反馈闭环最低配(只接显式纠正、只喂检索权重)。**补上"当天变聪明"。**
- **Phase 3 — 冷路径 Autodreaming v1:** 对账(commit / discard)+ 压缩 + 反思 + 遗忘。**护城河。**
- **Phase 4 — 按需扩展:** 扩反馈信号(加隐式信号、有界地喂偏好模型);并由指标 gate 重组件(时间图 / 反思内核)。

## 14. 非目标 / 明确放弃(防止复杂度反弹)

- ✗ 不从零造 "Memory OS 内核 / syscall DSL" —— 准入层是确定性函数 + 配置。
- ✗ 不默认用 LLM classifier 做准入 —— LLM 只作模糊个案升级通道。
- ✗ 不让反馈信号自动改写准入策略 —— 策略是人审配置,反馈只提"提案"。
- ✗ 不把在线更新直接写进长期 committed 状态 —— 必须 provisional + 夜间对账。
- ✗ 不同时引入两个能力重叠的图引擎;v1 不引入图引擎。
- ✗ 不把图遍历 / 同步 LLM 反思放热路径。
- ✗ 不把未经生产验证的研究框架当系统内核;不以刷 benchmark 为目标。

## 15. 风险与开放问题

- **护栏参数怎么定:** 在线更新的幅度上限、TTL、阻尼系数、provisional commit 阈值——靠 Phase 0 评估闭环调出来,不是拍脑袋。
- **隐式反馈又吵又难抽:** v1 只用显式纠正;隐式信号是 v2 的事,且只喂低风险通道。
- **对账逻辑有复杂度:** "该提交还是该丢弃"的规则要可解释;夜间作业质量(忘对没、洞察对不对)难自动评估,需人工抽检 + 用户反馈回灌。
- **偏好 schema 设计:** 条件化 + 时间有效区间的表达是 L3 核心待解。
- **"刚说的话"延迟:** Mem0 式异步写入意味着当轮内容可能下一拍才进长期记忆——用 L0 working memory 补这一拍,需确认体验可接受。
- **人格参数可控性:** disposition 参数怎么定义、怎么防漂移。
- **组件成熟度待核实:** 部分依赖(如压缩组件)定为关键依赖前先验证;压缩这步可先用自写离线 job 顶上。

## 16. 术语表

| 术语 | 含义 |
|---|---|
| 热 / 温 / 冷路径 | 按延迟预算划分的三条执行路径:实时读 / 异步写 / 夜间批处理 |
| Working / Episodic / Semantic / Preference | L0–L3 四层记忆 |
| Admission control(准入控制) | 决定一条信息存不存、存成什么、是否合并的写入策略层 |
| committed / provisional | 已提交的长期记忆 / 当天临时、可回滚、未提交的更新 |
| Reconciliation(对账) | 夜间把 provisional 更新提交或丢弃的过程 |
| Autodreaming | 夜间离线巩固作业:对账 + 压缩 + 反思 + 遗忘 + 人格更新 |
| Disposition 参数 | L3 中可调的人格 / 行为倾向参数 |
| 漂移(drift) | 系统在弱证据下错误改写长期记忆 / 人格,导致行为不稳定 |
| 三个时间尺度 | T0 即时 / T1 当天 provisional / T2 夜间 committed |

护城河 = **延迟优先的三路径架构 + 离线巩固**;关键安全机制 = **当天就变聪明,但每次变化都有界、可回滚、可观测,由夜间对账提交**。这条提交边界,决定了 Javis 是"可控进化",还是"看起来更聪明、实则记忆漂移"。

## 17. 多说话人 / 声纹集成(火山 RTC 原生 · 2026-06-29 优化)

> 新增产品要求(川哥):MyJavis 基于火山 RTC 打造,且要能**区分不同说话的人**(声纹识别)并**抑制背景人声**(声纹降噪)。
> 本节把这一要求整合进上面的记忆模型——核心结论:**说话人身份是记忆系统的"第一公民",不是可选标签。** 多人共享一台设备(家庭场景)时,记忆必须按说话人分账,否则爸爸的话被记到孩子头上 = 一种新的、最严重的记忆漂移。

### 17.1 火山 RTC 原生提供什么(已验证 · 火山官方文档《实时音视频 RTC 文档指南》§2.3.9/2.3.10,页 7479–7493)

声纹与降噪**全部是 `StartVoiceChat` 的配置项,零自建**(无需自建 pVAD/ECAPA/TSE):

| 能力 | 配置 | 关键约束(已验证) |
|---|---|---|
| **声纹识别(区分谁在说)** | `AgentConfig.VoicePrint.Mode=2` + `IdList`(声纹ID) + `Score`(阈值,推荐 40–60) | **单次通话最多识别 3 人**;仅流式 ASR 且 `StreamMode≠1` |
| **声纹降噪(只留主讲人)** | `AgentConfig.VoicePrint.Mode=1` | **单次通话仅 1 个目标用户**;公测中 |
| **说话人验证(只回复目标人)** | `VoicePrint.EnableSV=true` | 声纹比对成功才触发 AI 回复 = §9 "门控"的原生实现 |
| **远场人声抑制(滤 3–5 米外)** | `ASRConfig.FarfieldConfig`(Level/Threshold) | **仅火山语音识别大模型生效**;与声纹功能兼容 |
| **AI 降噪(滤非人声)** | `AgentConfig.AnsMode`(1/2/3) | ⚠️ **与声纹功能互斥**,启用声纹时勿开 |
| **声纹注册** | OpenAPI `RegisterVoicePrint`(拿 VoicePrintId)/`UpdateVoicePrint`;或通话中实时自学习(`VoiceDuration` 6/12/20s) | 注册与通话**采集设备需一致** |
| **声纹状态回调** | 客户端 `onRoomBinaryMessageReceived`,magic=`stat`,status: Disabled/Registering/Active | 前端已在解析二进制消息,加一个 `stat` 分支即可 |

**★ 与记忆系统的原生打通(这是关键,页 7486 已验证):** 开启声纹识别(Mode=2)后——
1. 实时字幕回调含 `voiceprintId` / `voiceprintName`;
2. 火山自动在送给 CustomLLM 的对话里注入 `(当前说话人是{AudioName})` 标签。
→ **我方 `custom-llm` 端点天然就知道"这一轮是谁在说",无需自建声纹推理,热路径零额外延迟。** 说话人身份是火山在热路径上"免费"送进来的元数据。

### 17.2 印证并落地了既有结论:"门控优于降噪"

记忆 `realtime_asr_speaker_discrimination_pvad_over_denoise`(姊妹项目 team 调研)的核心结论是:**"只认目标人"是门控问题(要不要响应),不是音质问题(音频干不干净);pVAD/声纹门控优于重型降噪(BVC/TSE)。** 当时该项目因**弃用火山 RTC**,只能走开源自建(ECAPA/pVAD)。

MyJavis **拥抱火山 RTC**,于是同一套智慧由火山原生兑现:
- "门控" = `EnableSV`(声纹验证) + 我方记忆准入按身份分账(见 §17.4);
- "区分人" = `Mode=2` 声纹识别 → 身份标签;
- 重型 TSE/BVC 自建那条路**整条砍掉**(火山声纹降噪/远场抑制顶上)。

### 17.3 关键配置取舍(已定:A 默认 + B 兜底,可切换) ✅

`VoicePrint.Mode` 单值:**`Mode=1`(降噪/单人) 与 `Mode=2`(识别/最多3人) 二选一**,且声纹功能与 AI 降噪(`AnsMode`)互斥。故:

| 方案 | 组合 | 得到 | 失去 | 适合 |
|---|---|---|---|---|
| **A(默认)** | `Mode=2` 识别 + `FarfieldConfig` 远场抑制 + 准入按身份门控 | 区分≤3人 + 滤远场 + 按人分账记忆 | 主动声纹降噪(背景人声不抹除,靠门控绕过) | 家庭多人共享、"记住每个人" |
| **B(兜底)** | `Mode=1` 降噪 + `EnableSV` + 远场抑制 | 只留1主人、强抗背景人声 | 多人区分(只认1人) | 强噪声环境、需硬抗背景人声时 |

**川哥拍板(2026-06-29):默认走 A;当需要强降噪效果时手动切 B。** A 符合"区分不同说话人"诉求 + "门控优于降噪"(区分到非目标人按身份不响应/不写记忆,而非抹音频)。

**切换机制(已验证·火山文档):`Mode` 是 `StartVoiceChat` 配置,`UpdateVoiceChat` 仅支持 `interrupt`/`function`,改不了声纹模式 → A↔B 切换必须重连**(stop 当前局 + 用另一 mode 重新 start)。`voiceMode` 设为 `/api/rtc/start` 的 start-time 参数(默认 `identify`=A,可选 `denoise`=B),前端给一个切换开关;重连耗时几秒,对低频切换可接受。
**记忆侧:B 是 A 的退化情形(单说话人)**——同一套 schema/准入,B 模式下所有记忆归属那 1 个目标用户,无需改数据模型。
**待确认:≤3 人识别上限对家庭场景是否够。**

### 17.4 对前面记忆模型的增量(schema + 准入)

**§3 数据模型增量——身份贯穿四层:**
- 新增 **Speaker Registry(身份层)**:`speaker_id(=voiceprintId) ↔ {name, profile_ref, enrolled_at, device_sig}`。`unknown` 为保留身份(未注册/未验证者)。
- **L1 EpisodicEvent.actor** 从 `user|agent` 升级为 `speaker_id|agent`(精确到具体人,不再笼统 "user")。
- **L2 Fact.subject / L3 Preference** 全部**按 speaker_id 分区**:每个人有独立的事实库与偏好/人格。Javis 对爸爸和孩子是同一个 Javis,但"记得的内容"按人隔离。

**§7 准入层增量——身份是准入的前置门:**
- `admit()` 新增输入 `speaker_id` + `speaker_confidence`(来自火山 `Score`)。
- **门控规则:** `unknown` 或 `speaker_confidence < 阈值` 的轮次 → 准入**降级**:可正常回复(通用语气),但**不写入任何人的长期记忆**(至多进 session 内 L0,session 结束丢弃)。防止"陌生人/电视里的人说的话"污染家人画像——这是多人场景下最高优先级的抗漂移红线。
- 显式纠正信号(§9)同样**按身份归属**:孩子纠正只能改孩子的记忆,不能改爸爸的。

**§2 延迟增量:** 说话人身份由火山在字幕/标签里热路径免费下发,我方热路径**不增加**身份推理开销(对齐 ≤200ms 预算)。

### 17.5 非目标增量(补 §14)

- ✗ **不自建声纹/pVAD 引擎**——火山 RTC 原生提供声纹识别/降噪/远场抑制/验证,自建是重复造轮子(姊妹项目因弃 RTC 才自建)。
- ✗ **不把记忆护城河外包给火山 VikingDB 托管记忆库**——火山"接入记忆库(长期记忆)"基于 VikingDB,属本 PD §0.3 点名的"商品化向量召回"那一环。我们只用火山的**语音 I/O + 声纹身份**,记忆的准入/巩固/遗忘/人格(护城河)全部自建自控。VikingDB 至多作为评测期的对照基线,不作主存。
- ✗ 不在声纹未生效(Registering)时就按身份写记忆——以 `stat` 回调的 `Active` 为准。

## 18. v2 修订(team 对抗评审后 · 2026-06-30 · 川哥拍板)

> grok+codex 两发独立强收敛,指出 v1 几处根本问题。本节**取代**正文中冲突的设计;完整裁决见 [`REVIEW-memory-team-2026-06-30.md`](REVIEW-memory-team-2026-06-30.md),实现见 [`Javis-Memory-架构与逻辑.md`](Javis-Memory-架构与逻辑.md) v2.0。

**取代正文的 5 处:**

1. **§5/§7 对账规则改了**:`reinforced_count ≥ N 才 commit` **错**——会系统性遗忘一次性高价值事实("我明天6点航班""对青霉素过敏"说一次没重复 → 夜里 discard → 忘了)。**改为 typed 记忆生命周期**:按类型(event/reminder/preference/profile/safety/ephemeral)各自定 commit + 有效期 + 冲突策略;显著/安全类一次直通 committed,不等强化。

2. **提交边界保留但 reconcile 引擎砍**(cc 折中,川哥准):provisional/committed 概念保留(status+TTL,保住抗漂移意图);砍掉重型夜间 Autodreaming reconcile;commit 由 typed 策略驱动。**§10 Autodreaming 的压缩/反思/人格塑形 = MVP 暂缓**(易生成无 provenance 幻觉画像),冷路径 MVP 只做 TTL+去重+冲突 compaction+指标。

3. **§0.3 护城河重定义**:"延迟优先三路径 + 离线巩固"中,**离线巩固机制本身不是护城河**(夜间批+LLM总结+向量库谁都能抄)。**真护城河 = 长期个体化数据 + 高质量纠错闭环 + 低串账率 + 信任/隐私治理 + 可回放评测体系 + 实时体验**,用指标定义。

4. **§13 路线图改 MVP 减法**:暂缓 L2 通用三元组 / 人格 disposition / 反思内核 / 三路并行召回 / 向量召回(证明"查不准"再上),逐层由指标 gate。这是落实 §1 原则 3"先证明价值再加层"——v1 自己违反了它。

5. **§7 准入措辞修正**:不自称"确定性优先"(salience 本质语义判断)。**hybrid**:确定性层管边界/安全/去重/schema/风控,语义层(LLM)管候选理解但被规则层 veto、输出结构化、不得直接 commit。

**新增的红线/能力(v1 漏了):**

- **身份证据层(致命)**:火山 `voiceprintId` **不能当长期记忆主键**(6-20s 自学习竞态 + 最多3人 + 第4人 + Score 概率判断 → 串账)。引 SpeakerEvidence 状态机 + memory_owner_id + quarantine + IdentityAdapter;非 active_stable 不写长期。
- **事件溯源轮(致命)**:全双工 barge-in 破坏"完整(user,assistant)对"。改事件溯源:只从 finalized user utterance 抽取;`source_role` 溯源(assistant 文本不作用户事实);幂等 event log 防丢写。
- **记忆作 data 不作 instruction(安全致命)**:记忆来自不可信语音,原样拼 systemPrompt = 持久化越狱。结构化渲染 + 注入防御 + 测试集 + 禁存改安全/权限的"偏好"。
- **隐私治理 + 共享记忆**:namespace(private/shared/session/device)+ ACL + 治理入口(查看/忘掉/重归属/暂停/导出)+ 敏感短TTL/加密;纠正带权限(防跨 owner 污染)。
- **延迟预算拆分**:200ms 含火山RTT 不现实。拆成 网络RTT单算 / memory read p95≤50-80ms / assembly≤20ms / LLM TTFT 单算。
- **Phase0 新增指标**:串账率、一次性关键事实保留率、prompt injection 抵抗率、纠正恢复时间。
